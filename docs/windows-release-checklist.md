# Windows 打包链路手工验收清单

## 目标

- 发版前用一轮轻量手工回归确认 Windows 打包主链路没有明显回归。
- 验收重点不是覆盖所有分支，而是确认成功链路稳定、失败链路可提示、日志可定位。

## 固定样例

- 样例 A：普通小作品，用于验证基础成功链路。
- 样例 B：资源较多或体积较大的作品，用于验证性能和稳定性。
- 样例 C：故意异常的输入，用于验证错误提示和日志链路。

## 正常作品

- [ ] 选择样例 A，确认能完成转换与打包。
- [ ] 确认导出目录中成功生成 Windows 产物。
- [ ] 确认完成页的“打开输出目录”可正常打开。
- [ ] 确认产物名称、图标、作品名称符合预期。

## 较大作品

- [ ] 选择样例 B，确认流程不会明显卡死或异常中断。
- [ ] 确认最终仍能成功生成产物并复制到导出目录。
- [ ] 确认构建期间进度文本、阶段切换和完成态显示正常。

## 异常输入

- [ ] 使用损坏或非法 `.bcm` 文件，确认会提示错误而不是直接崩溃。
- [ ] 使用无效图标或不支持格式的图标，确认提示文案可理解。
- [ ] 选择不可写目录或受限目录，确认失败提示可理解。
- [ ] 确认异常场景下不会生成误导性的“成功结果”。

## 缓存与权限

- [ ] 连续执行两次打包，确认首次下载和二次缓存复用都正常。
- [ ] 如触发 Windows 权限限制，确认提权重试链路仍可继续打包。
- [ ] 确认打包产物会复制到用户选择的导出目录，而不是只停留在内部工作目录。

## 日志与排查

- [ ] 打包失败时确认日志会落盘。
- [ ] 确认失败弹窗在需要时可手动打开日志。
- [ ] 确认日志内能看到阶段、错误码、输出目录、缓存目录和关键错误摘要。

## 通过标准

- 通过：成功链路完成，失败链路可提示、可落日志、可定位。
- 阻塞发版：正常作品打包失败、导出复制失败但界面无说明、打开输出目录失效、失败不落日志、较大作品明显卡死或崩溃。
- 可带病发版：少量文案不够优雅、少数非关键进度文案不准确、日志摘要展示还不够理想。
